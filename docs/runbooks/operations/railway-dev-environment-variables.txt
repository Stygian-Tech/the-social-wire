THE SOCIAL WIRE - RAILWAY DEV ENVIRONMENT VARIABLES
===================================================

Railway project: The Social Wire
Railway environment: dev

This file lists the application variables required for the Railway Dev environment.
It intentionally contains no real secret values.

Status labels:
  ALREADY SET     Present in Railway Dev now.
  USER INPUT      A real value still needs to be supplied.
  GENERATED       Create a unique Dev-only secret; never copy the Production value.
  OPTIONAL        Leave unset unless the described feature is enabled.
  RAILWAY MANAGED Railway creates this automatically; do not set it by hand.


VALUES STILL NEEDED FROM AN OPERATOR
====================================

1. Operator DID allowlist

   Set the same comma-delimited DID list in both locations:

   Operations Web:
     NEXT_PUBLIC_OPERATIONS_OPERATOR_DIDS=did:plc:...

   Ops:
     OPERATIONS_OPERATOR_DIDS=did:plc:...

   The Operations Web value controls client-side visibility. The Ops value is the
   authoritative server-side authorization check.

2. L@tr Link credentials for the Web frontend

   Set one of these credential forms on Web:

   Preferred:
     LATR_GATEWAY_CLIENT_CREDENTIAL=<Dev official client credential>

   Or, instead of the preferred variable:
     LATR_GATEWAY_CLIENT_ID=<Dev client ID>
     LATR_GATEWAY_API_KEY=<Dev API key>

3. L@tr Link credentials for the iOS proxy routes

   Set one of these credential forms on Gateway:

   Preferred:
     LATR_IOS_PROXY_CLIENT_CREDENTIAL=<Dev official client credential>

   Or, instead of the preferred variable:
     LATR_IOS_PROXY_CLIENT_ID=<Dev client ID>
     LATR_IOS_PROXY_API_KEY=<Dev API key>

The core Web, Gateway, App View, worker, Tap, and Postgres configuration is already
present. The three items above are needed for Operations access and complete L@tr
functionality.


POSTGRES SERVICE: Postgres
==========================

No application variables need to be entered manually on this service.

RAILWAY MANAGED:
  DATABASE_URL
  PGHOST
  PGPORT
  PGDATABASE
  PGUSER
  PGPASSWORD
  POSTGRES_DB
  POSTGRES_USER
  POSTGRES_PASSWORD
  PGDATA

DATABASE_PUBLIC_URL is Railway-managed and exists only while a public TCP proxy is
enabled. Application services must use the private DATABASE_URL reference instead.
Do not keep a public Postgres TCP proxy enabled after migration work.

  LATR_IOS_PROXY_URL=https://api.testing.latr.link
  LATR_IOS_PROXY_CLIENT_CREDENTIAL=<secret>

OR use both of these instead of LATR_IOS_PROXY_CLIENT_CREDENTIAL:
  LATR_IOS_PROXY_CLIENT_ID=<Dev client ID>
  LATR_IOS_PROXY_API_KEY=<Dev API key>

  CORS_ALLOWED_ORIGINS=https://web-dev-88e4.up.railway.app,https://operations-web-dev.up.railway.app
  OAUTH_IOS_METADATA_ORIGIN=https://gateway-dev-4009.up.railway.app

The CORS variable is optional because Gateway currently derives both origins from
OAUTH_PUBLIC_ORIGIN and OAUTH_OPERATIONS_ORIGIN. Leave the known-client switch false
for Dev unless every accepted Web, Operations, and iOS client ID is explicitly added
to OAUTH_GATEWAY_ALLOWED_CLIENT_IDS.

SHARED SECRET PAIRING RULES
===========================

Generate independent Dev values with a cryptographically secure generator such as:
  openssl rand -hex 32

Pair 1:
  Gateway.GATEWAY_APPVIEW_INTERNAL_SECRET
  App View.GATEWAY_APPVIEW_INTERNAL_SECRET

Pair 2:
  Gateway.GATEWAY_OPERATIONS_INTERNAL_SECRET
  Ops.GATEWAY_OPERATIONS_INTERNAL_SECRET

Pair 3:
  Tap.TAP_ADMIN_PASSWORD
  Charybdis.TAP_ADMIN_PASSWORD

Each pair must match internally. The three pairs must be different from one another
and different from their Production equivalents.


RAILWAY-GENERATED VARIABLES
===========================

Do not manually create or copy variables whose names begin with RAILWAY_. Railway
injects project, environment, service, private-domain, public-domain, and volume
metadata separately for each service instance.


IF DEV CUSTOM DOMAINS REPLACE THE TEMPORARY RAILWAY DOMAINS
===========================================================

Update these values together:

Web:
  NEXT_PUBLIC_SITE_URL=<Dev Web origin>
  NEXT_PUBLIC_SOCIALWIRE_API_URL=<Dev Gateway origin>

Operations Web:
  NEXT_PUBLIC_OPERATIONS_GATEWAY_ORIGIN=<Dev Gateway origin>

Gateway:
  OAUTH_PUBLIC_ORIGIN=<Dev Web origin>
  OAUTH_OPERATIONS_ORIGIN=<Dev Operations Web origin>
  OAUTH_OPERATIONS_CLIENT_ID=<Dev Gateway origin>/operations-oauth-client-metadata.json
  OAUTH_IOS_METADATA_ORIGIN=<Dev Gateway origin>

If CORS_ALLOWED_ORIGINS is set, replace its origins at the same time. Domain changes
also require Railway domain attachment, DNS, and certificate activation; variables
alone do not route traffic.
